# API Documentation

Local base URL: `http://localhost:5000/api`. The Vite development server proxies
browser `/api` requests to this API. JSON request/response bodies are used.

## Availability and errors

- `GET /health` is database-independent and returns `200`, including
  `database: connected|connecting|disconnected`.
- Database-dependent routes return `503` with `{ "error": "Database is
  unavailable", "database": "..." }` until MongoDB connects.
- Validation errors return `400`; missing records/routes return `404`;
  duplicate unique values return `409`; unexpected errors return `500` with a
  JSON message.

Example:

```json
{ "error": "Invalid region", "details": { "allowedRegions": ["north", "south", "east", "west"] } }
```

## Weather stations

| Method | Path | Description |
|---|---|---|
| GET | `/stations` | List stations; optional `region`, `status`, `search`, and `limit` query parameters. Includes latest reading and reading count. |
| GET | `/stations/:stationId` | Fetch one station and its reading summary. |
| POST | `/stations` | Create station; returns `201`. |
| PUT | `/stations/:stationId` | Update station fields. |
| DELETE | `/stations/:stationId` | Delete station; historical readings and alerts are retained. |

Create payload:

```json
{
  "stationId": "SKY-N-9001",
  "stationName": "North Ridge",
  "region": "north",
  "latitude": 64.8,
  "longitude": -147.7,
  "city": "Fairbanks, Alaska"
}
```

`stationId` may be omitted and generated by the API. Region and geographic
coordinates are validated.

## Weather readings

| Method | Path | Description |
|---|---|---|
| GET | `/readings` | Query latest readings across regions; optional `region`, `stationId`, `from`, `to`, `limit`. |
| GET | `/readings/region/:region` | Query one logical reading collection; accepts the same filters. |
| POST | `/readings/query` | Execute a routed, scatter-gather, multi-region, or global query with collection access and explain metrics. |
| POST | `/readings/benchmark` | Compare routed and scatter-gather queries using the same regional/station/time filters. |
| GET | `/readings/query-history` | Return recent query-analysis executions held in this API process. Optional `limit` (1-100). |
| POST | `/readings` | Store a reading in the station's assigned region; returns `201`. |
| POST | `/readings/simulate` | Generate controlled, marked simulated readings for a station, region, or up to 20 stations. |
| GET | `/readings/trends` | Return aggregated trends; optional `region`, `stationId`, `range` (`24h`, `7d`, `30d`). |

Create reading payload:

```json
{
  "stationId": "SKY-N-9001",
  "temperature": 12.4,
  "humidity": 54,
  "windSpeed": 3.2,
  "atmosphericPressure": 1012,
  "rainfall": 0.1,
  "recordedAt": "2026-11-11T12:00:00.000Z"
}
```

The API looks up the station and routes to its assigned collection. An optional
`region` must match that station; client input never selects a MongoDB
collection. Generated observations have `simulated: true` and are not sensor
telemetry.

### Query analysis payloads

One strategy:

```json
{
  "strategy": "routed",
  "stationId": "SKY-S-2068",
  "from": "2026-11-01T00:00:00.000Z",
  "limit": 50
}
```

`strategy` is `routed`, `scatter-gather`, `multi-region`, or `global`.
`routed` requires `region` or `stationId`; a station's assigned region is
looked up server-side. `multi-region` accepts `regions: ["south", "east"]`.
`scatter-gather` optionally takes a region predicate but always accesses all
four regional collections. `global` searches all four without a region
predicate. All strategies accept `stationId`, `from`, `to`, and `limit`.

The result includes `records`, `executionTimeMs`, `documentsExamined`,
`documentsReturned`, `keysExamined`, `indexUsage`, `explainAvailable`,
`collectionsAccessed`, `regionalCollectionAccessCount`, and
`collectionMetrics` (per-regional-collection explain and returned-document
metrics). For station queries `WeatherStations` is included in
`metadataCollectionsAccessed`; collection access counts distinguish regional
data collections from this lookup. Unavailable explain metrics are `null` and
should display as `N/A`.

The benchmark body accepts `region` or a station and the same optional
`from`/`to`/`limit` filters:

```json
{ "region": "south", "from": "2026-11-01T00:00:00.000Z", "limit": 50 }
```

It returns `routed` and `scatterGather` query results with the same filter and
limit. Elapsed times measure the API's actual result retrieval; explain requests
are made separately to collect execution statistics. There is no artificial
delay or assumed speed advantage. Cache state, indexes, data volume, load, and
environment can affect each measurement. Query history is process-local and
resets when the backend restarts.

## Dashboard

| Method | Path | Description |
|---|---|---|
| GET | `/dashboard/stats` | Total/active stations, readings, region count, average weather values, and active alert count. |
| GET | `/dashboard/overview` | Recent stations with latest readings, regional aggregates, and 24-hour trend. |
| GET | `/dashboard/trends` | Aggregated temperature, humidity, and reading-count trend; accepts `region`, `stationId`, and `range`. |

## Regional database

| Method | Path | Description |
|---|---|---|
| GET | `/regions` | Four region definitions, collection names, station counts, reading counts, averages, and distribution. |
| GET | `/regions/:region` | One region summary. |
| GET | `/regions/:region/stats` | One region's station, reading, average, status, and distribution statistics. |

Supported region keys: `north`, `south`, `east`, and `west`. Names such as
`North Region` are also accepted by the router.

## Alerts

| Method | Path | Description |
|---|---|---|
| GET | `/alerts` | List alerts; optional `status`, `severity`, `region`, and `limit`. |
| POST | `/alerts` | Create an alert for an existing station; returns `201`. |
| PATCH | `/alerts/:alertId/resolve` | Mark an alert resolved and set `resolvedAt`. |

Create payload:

```json
{
  "stationId": "SKY-N-9001",
  "alertType": "high_temperature",
  "severity": "warning",
  "message": "Temperature is above threshold."
}
```

## Aggregation and routing notes

Regional average temperature/humidity and reading totals use aggregation
pipelines over the four collections. Overall stats combine regional data;
temperature trends group readings with MongoDB `$dateTrunc`. Station counts
group `WeatherStations` by region/status. Distribution is each region's reading
count divided by all readings. This application-level routing is not MongoDB's
native sharding router.

## Operational notes

- The local development backend defaults to port `5000`; Vite proxies `/api`
  from its development server to `http://localhost:5000`.
- `GET /health` may return HTTP `200` with `database` set to `connecting` or
  `disconnected`; this indicates HTTP service health, not database readiness.
  Database-backed endpoints return `503` until MongoDB is available.
- The seed command is `cd backend; npm run seed`. It upserts 20 stations, 200
  deterministic readings, and five alerts. Additional simulated readings can
  change the live collection counts.
- `/readings/query-history` is an in-memory operational/demo history limited to
  the current backend process; it is not durable audit logging.
- Query timing and explain metrics are observations from the configured
  MongoDB deployment. Metrics unavailable from an explain plan are returned as
  null and should be displayed as N/A.

measured local benchmark runs. The values in that report are not universal
performance claims.
